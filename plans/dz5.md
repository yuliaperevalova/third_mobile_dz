Проект остаётся на том же стеке:

- **Compose only**

- coroutines / `viewModelScope`

## Обязательные требования

### 1) Проект из прошлой ДЗ остаётся рабочим

В проекте должны остаться:

- 2+ экрана: **List/Search** и **Detail/{id}**
- Navigation Compose
- Retrofit
- Room
- Hilt
- UI-состояния: **Loading / Error + Retry / Empty / Success**

---

### 2) Обязательны юнит-тесты

Нужно написать **минимум 6 юнит-тестов**.

Обязательно покрыть:

- успешную загрузку данных
- ошибку загрузки
- `retry()` после ошибки
- корректное начальное состояние экрана

Дополнительно ещё **минимум 2 юнит-теста** на слой данных / бизнес-логику, например:

- отсутствие дублей в избранном / истории / кеше
- корректное преобразование моделей
- корректная обработка пустого результата
- корректная обработка `SavedStateHandle`

---

### 3) Обязательны интеграционные тесты

Нужно написать **минимум 3 интеграционных теста**.

Среди них обязательно должны быть:

#### a) Хотя бы 1 тест на интеграцию data-слоя

Одна из связок:

- `Repository + Room`
- `Repository + Fake API + Room`

#### b) Хотя бы 1 тест на интеграцию UI

Один из сценариев:

- список -> клик по элементу -> переход на детали
- ошибка -> нажатие `Retry` -> успешное состояние
- отображение корректного состояния экрана после загрузки данных

---

### 4) Нетривиальных тесты

Должно быть **минимум 2 нетривиальных теста**.

Под нетривиальными понимаются тесты, которые проверяют **контракт поведения**, а не только финальное значение.

Примеры допустимых сценариев:

- `retry()` действительно инициирует **новую попытку запроса**
- повторное добавление в избранное **не создаёт дубль**
- пустой результат поиска даёт именно **Empty**, а не `Success(emptyList())`
- переход на детали открывает экран именно для **нужного id**
- после записи в Room данные корректно читаются повторно
- состояние после ошибки и повторной загрузки переходит корректно

---

### 5) Тесты должны быть детерминированными

## Отдельное обязательное требование для проектов с Flow

**Если в проекте используется `Flow` / `StateFlow` / `SharedFlow`, добавляется отдельный обязательный пункт.**

Обязательно:

- минимум **1 тест** на **полную последовательность эмиссий**
- минимум **1 тест** на **нетривиальное потоковое поведение**

В качестве нетривиального потокового поведения засчитывается одно из:

- отмена устаревшего запроса и недопущение старого результата в UI
- отсутствие лишних / дублирующихся эмиссий
- корректное поведение при новой подписке
- корректное разделение state и one-time events

**Если в тестах проверяется только конечный `state.value`, пункт считается невыполненным.**
